## About Me

I'm a Computer Science undergraduate specialising in **Machine Learning and AI**, with a strong pull toward the part most student projects skip: taking a model or an idea and turning it into a **working, deployed, evaluated system**. Most of what's below isn't a notebook that stops at a metric — it's an API, a live demo, a dashboard, or a UI someone else can actually use.

Lately that's meant **agentic RAG** (LangGraph-based agents that decide when to retrieve, grade their own context, and abstain instead of hallucinating), **cost-sensitive ML** (calibrating decision thresholds instead of defaulting to 0.5), and **shipping on free infrastructure** (Hugging Face Spaces, Render, Vercel) without pretending cost doesn't matter.

- 🔭 Currently building **agentic and evaluation-driven RAG systems** (LangGraph, FastAPI, vector search)
- 🧠 Deepening my grip on **cost-sensitive & imbalanced-data ML** — calibration, thresholds, PR-AUC over accuracy
- 🛠️ Full-stack when the project needs it: **React/TypeScript + FastAPI/Node** with real auth, tests, and deployment
- 📊 Also comfortable one layer up the stack: **SQL + Power BI** turning raw data into a business case
- 🌱 Learning: reranking & hybrid retrieval, production monitoring for ML services, multi-agent orchestration
- 💬 Ask me about: RAG pipelines, LangChain/LangGraph, imbalanced classification, or why I picked HistGBM over a neural net

## Featured Projects

### 🤖 [Agentic RAG](https://github.com/nidixh/agentic-rag) — self-correcting retrieval agent
An adaptive RAG service built on **LangGraph**, not a plain retrieve-then-generate chain: it routes queries (retrieve vs. answer directly vs. refuse), grades its own retrieved context, reformulates weak queries, checks its own output for grounding, and abstains rather than hallucinate. Ships with a reproducible eval harness scoring retrieval hit-rate, faithfulness, correctness, and refusal accuracy — plus an ablation proving the grounding gate trades a little correctness for eliminating hallucinations (faithfulness 1.00 → 0.43 when disabled).
- **Result:** 1.00 retrieval hit-rate@4, 1.00 faithfulness, 1.00 refusal accuracy on a mixed in-scope / out-of-scope / prompt-injection eval set
- **Stack:** FastAPI · LangGraph · Chroma · Ollama (local, free) / Groq (cloud swap via one env var)
- 🔗 **[Live demo](https://nidixh-agentic-rag.hf.space/docs)** &nbsp;·&nbsp; [Source](https://github.com/nidixh/agentic-rag)

### 💬 [DocChat](https://github.com/nidixh/docchat) — full-stack RAG app with real auth
Upload a document, ask questions, get token-streamed answers grounded in its content. Not a demo script — it has JWT auth with bcrypt hashing, Alembic-migrated SQLAlchemy models, a provider-swappable LLM layer (Ollama locally, Gemini in production, one env var apart), and **30 backend + frontend tests** running fully offline against a deterministic fake LLM.
- **Stack:** FastAPI · React 19 + TypeScript · SQLAlchemy/Alembic · SSE streaming
- **Deployed:** Vercel (frontend) → Render (API) → Gemini free tier
- 🔗 [Source](https://github.com/nidixh/docchat)

### 🏥 [Hospital Readmission Risk Detector](https://github.com/nidixh/Hospital_Readmission_Risk_Detector) — end-to-end ML lifecycle
Predicts 30-day hospital readmission and answers the real operational question: *who gets a follow-up call?* Compares Logistic Regression, HistGBM, and a PyTorch MLP honestly (the neural net doesn't win — and the README says so), calibrates probabilities with isotonic regression, and picks a decision threshold by minimizing expected cost under a documented 10:1 false-negative/false-positive ratio — not the default 0.5.
- **Result:** catches 62% of true readmissions at the calibrated threshold; served via FastAPI with a live drift-monitoring endpoint (per-feature PSI)
- **Stack:** scikit-learn + PyTorch · FastAPI · MLflow · Docker · 22 pytest cases
- **Deployed:** Hugging Face Spaces (Docker)
- 🔗 [Source](https://github.com/nidixh/Hospital_Readmission_Risk_Detector)

### 🏠 [Roomify AI](https://github.com/nidixh/Roomify-AI) — AI interior/architecture visualizer
Upload a photo of a room, generate a redesigned concept, and compare before/after with an interactive slider. Built as a modern product, not a script: authenticated user flow, AI-generation pipeline, and project save/retrieval, containerized for deployment.
- **Stack:** React Router · TypeScript · Vite · Puter (auth, AI generation, storage) · Docker
- 🔗 [Source](https://github.com/nidixh/Roomify-AI)

### 💳 [Credit Default Prediction](https://github.com/nidixh/Credit-Default-Prediction) — deep learning on imbalanced risk data
An end-to-end deep learning pipeline for credit-default classification, run as a disciplined experiment rather than one-shot training: a baseline first, then an architecture sweep across 6 network sizes (multiple seeds each), a regularization sweep (L2 vs. dropout vs. both), and threshold calibration on the validation set before ever touching the test set.
- **Result:** calibrating the threshold lifted recall from **0.33 → 0.81** at a comparable F2-score trade-off; final **Test ROC-AUC 0.7717**, **Test Recall 0.8080**
- **Stack:** TensorFlow/Keras · scikit-learn · Keras Tuner
- 🔗 [Source](https://github.com/nidixh/Credit-Default-Prediction)

### 📊 [Customer Shopping Behavior Analysis](https://github.com/nidixh/customer_behavior_analysis) — data analytics end-to-end
Full analytics workflow on 3,900 transaction records: Python/Pandas cleaning and feature engineering, business questions answered in SQL against a PostgreSQL table, an interactive Power BI dashboard, and a written stakeholder report with concrete recommendations (subscription incentives, loyalty targeting, discount strategy).
- **Stack:** Python · Pandas · PostgreSQL · Power BI
- 🔗 [Source](https://github.com/nidixh/customer_behavior_analysis)
